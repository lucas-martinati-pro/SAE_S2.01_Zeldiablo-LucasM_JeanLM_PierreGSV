# Fonctionnalités prévues version 2

- fonctionnalité 1 : Gestion des niveaux
  - descriptif texte : Le zeldiablo est constitué de plusieurs niveaux.
  - critères de validation :
    - critère 1 : Un niveau décrit le labyrinthe et les monstres qui y sont contenus.
    - critère 2 : Il est possible de choisir le niveau à lancer au démarrage de l'application (en modifiant la chaîne de caractère passée dans le main).
    - critère 3 : Testez en ajoutant un second niveau à définir au préalable.
  - responsables : GALLOIS Pierre

- fonctionnalité 2 : Fin du zeldiablo : mort du héros
  - descriptif texte : Lorsque le héros n'a plus de points de vie, le zeldiablo s'arrête et la partie est perdue.
  - critères de validation :
    - critère 1 : Le héros par défaut dispose de 5 points de vie.
    - critère 2 : Chaque monstre fait 1 point de dégât lorsque le héros se fait attaquer.
    - critère 3 : Quand le héros meurt, un message de fin est affiché sur la console et le zeldiablo s'arrête.
  - responsables : LE MADEC Jean

- fonctionnalité 3 : Cases piégées
  - descriptif texte : Lorsque une entité (héros ou monstre) arrive sur une case piégée, il subit des dégâts.
  - critères de validation :
    - critère 1 : Les dégâts ne se déclenchent que lorsque le joueur arrive sur la case, il peut ensuite rester sur cette case aussi longtemps qu'il le souhaite sans subir d'autres dégâts.
    - critère 2 : Lorsque la case devient à nouveau vide, le piège se réamorce.
    - critère 3 : (optionnel) Lorsqu'une case a été détectée comme un piège, elle s'affiche différemment dans le labyrinthe (en brun) ce qui permet au joueur d'en tenir compte ensuite.
  - responsables : MARTINATI Lucas

- fonctionnalité 4 : Attaque du joueur
  - descriptif texte : Lorsque le joueur appuie sur une touche donnée (par défaut la touche espace), il exécute une attaque contre les monstres qui se trouvent à côté de lui.
  - critères de validation :
    - critère 1 : L'attaque a effectivement lieu quand le joueur appuie sur la touche.
    - critère 2 : TOUS les monstres à côté du joueur prennent un point de dégât.
    - critère 3 : TOUS les monstres éloignés du joueur ne subissent pas de dégâts.
    - critère 4 : S'il n'y a aucun monstre autour du joueur, l'attaque à quand même lieu et empêche le déplacement du joueur, mais les monstres ne prennent pas de dégâts.
  - responsables : GALLOIS Pierre

- fonctionnalité 5 : Dégâts d'une bombe
  - descriptif texte : Lorsqu'une bombe explose, des langues de feu jaillissent horizontalement et verticalement et font des dégâts sur les cases atteintes.
  - critères de validation :
    - critère 1 : La bombe n'est déclenchée que quand son timer arrive à 0.
    - critère 2 : Les langues de feu ne se propagent que horizontalement et verticalement.
    - critère 3 : Les langues de feu ont une taille donnée (par exemple elles ne se propagent que de 3 cases dans chaque direction).
    - critère 4 : Les murs et les obstacles bloquent la propagation des langues de feu.
    - critère 5 : Tous les personnages traversés par les langues de feu subissent des dégâts.
  - responsables : MARTINATI Lucas

- fonctionnalité 6 : Dépôt d'une bombe
  - descriptif texte : Un héros attaque désormais en posant des bombes sur sa case. Les bombes déposées sont en nombre limité, leur timer est initialisé lorsqu'elles sont posées.
  - critères de validation :
    - critère 1 : Lorsqu'un héros décide d'attaquer, il pose une bombe sur sa case.
    - critère 2 : Le héros peut sortir de sa case, mais la case de la bombe n'est plus traversable tant que la bombe n'a pas explosé.
    - critère 3 : Lorsque le timer de la bombe arrive à 0, la bombe explose et effectue des dégâts.
    - critère 4 : Un héros dispose d'un nombre maximal de bombes posées simultanément : il ne peut pas poser plus de 3 bombes simultanément sur le labyrinthe.
    - critère 5 : Une fois qu'une bombe a explosé, le héros peut à nouveau poser une bombe en remplacement sur le labyrinthe.
  - responsables : MARTINATI Lucas

- fonctionnalité 7 : Murs friables
  - descriptif texte : Certaines cases du labyrinthe sont des murs friables qui peuvent être détruits par des bombes.
  - critères de validation :
    - critère 1 : Un mur friable est un type de case du labyrinthe.
    - critère 2 : Un mur friable n'est pas traversable (tant qu'il n'est pas détruit).
    - critère 3 : Lorsqu'une explosion de bombe rencontre un mur friable, le mur friable empêche la propagation de l'explosion dans cette direction. Il est considéré comme détruit et peut ensuite être traversé.
  - responsables : LE MADEC Jean

- fonctionnalité 8 : Génération de monstres immobiles
  - descriptif texte : Au lancement du jeu, le jeu ajoute différents monstres dans l'environnement. Les monstres restent immobiles.
  - critères de validation :
    - critère 1 : Il est possible de construire un labyrinthe par défaut contenant quelques monstres (le labyrinthe par défaut est à définir).
    - critère 2 : Les monstres sont créés sur des cases vides.
    - critère 3 : Il n'est pas possible de générer des monstres sur des cases non vides (position du joueur, d'autres monstres ou de murs)
    - critère 4 : Les monstres doivent apparaitre dans l'interface graphique sous la forme d'un cercle rouge.
    - critère 5 : Les monstres ne se déplacent pas (mais attaquent éventuellement le héros s'il passe à proximité.
  - responsables : MARTINATI Lucas

- fonctionnalité 9 : Déplacement aléatoire des monstres
  - descriptif texte : Régulièrement, le jeu demande aux monstres de se déplacer dans une direction aléatoire.
  - critères de validation :
    - critère 1 : A chaque évolution du jeu, que le joueur se déplace ou non, les monstres se déplacent.
    - critère 2 : Les monstres sont bloqués par les obstacles. S'ils ont choisi de se diriger vers un obstacle (mur, joueur, ...), leur mouvement est alors annulé (sauf s'il s'agit de fantômes).
    - critère 3 : Deux monstres ou un monstre et un joueur ne peuvent pas se trouver sur la même case (Si la tache Collision entre monstre est fonctionnelle).
    - critère 4 : A chaque évolution, tous les monstres tentent de se déplacer.
    - critère 5 : L'interface graphique se met à jour en fonction des déplacements des Monstres.
  - responsables : MARTINATI Lucas

- fonctionnalité 10 : Gestion d'un labyrinthe multi-étages
  - descriptif texte : Le labyrinthe est constitué de plusieurs étages. Chaque étage correspond à un niveau particulier. Des escaliers permettent de passer d'un étage à un autre.
  - critères de validation :
    - critère 1 : Les escaliers sont des cases traversables par le héros et les monstres.
    - critère 2 : Lorsque le héros se trouve sur un escalier, il peut l'activer et il change alors de niveau.
    - critère 3 : Les monstres du niveau où le héros se trouvait avant l'escalier n'apparaissent pas dans l'étage supérieur/inférieur. Ils restent à leur position et conservent leur points de vie.
    - critère 4 : De nouveaux monstres peuvent être présents à l'étage supérieur en fonction du descriptif du niveau.
    - critère 5 : Le Héros arrive aux mêmes coordonnées dans l'étage supérieur/inférieur après avoir emprunté les escaliers.
    - critère 6 : Les escaliers peuvent être de deux types : un escalier qui monte ou un escalier qui descend.
    - critère 7 : Les escaliers sont empruntables dans les deux sens : un escalier qui monte vers un étage possède un escalier qui descend à la même position dans l'étage supérieur (et inversement).
  - responsables : LE MADEC Jean

- fonctionnalité 11 : Affichage avec des sprites
  - descriptif texte : La fenêtre n'affiche plus des figures de base (rond, ...) mais des sprites représentant les personnages et les objets.
  - critères de validation :
    - critère 1 : Les sprites concernent les murs, les monstres et le héros.
    - critère 2 : Ils sont chargés une fois pour toute au lancement de l'application et ils peuvent être affichés dans le JPanel grâce à la méthode drawImage.
    - critère 3 : Vous pourrez utiliser l'image http://www.qcfdesign.com/?p=354 qui est un ensemble de sprites pour le jeu Desktop Dungeons. Ces sprites sont disposés régulièrement dans l'image et sont donc facile à extraire à partir de l'Image.
    - critère 4 : Il est possible de charger une image (de type BufferedImage en mémoire grâce à la classe ImageIO et la méthode statique read).
